# 商品・在庫・棚卸の紐づきと端末別表示設計

## 目標
「共通の商品情報は一か所で変更してすべての現在の業務画面へ反映」「ロット固有の実績・過去履歴は勝手に変えない」「PCで1商品が一行の横幅を占有しない」を同時に実現する。

## データの正本と反映先
| 項目 | 正本 | 現在表示での反映 | 変更しないもの |
|---|---|---|---|
| 商品名・JAN・システムJAN・共通メーカー | Item | 商品一覧・商品詳細・棚卸検索の関連Item参照 | 過去操作の監査ログ |
| 大分類・小分類・既定単位 | Item | 同じ商品に紐づく在庫の継承値、商品検索、棚卸範囲、期限管理の現在の表示 | 在庫明細で意図して異なる値を指定した個別設定 |
| ロット・数量・期限・保管場所・在庫区分 | InventoryInstance | 在庫一覧・詳細・進行中の棚卸検索で最新の関連在庫を参照 | 別ロットの値 |
| 棚卸対象から外す | Item / InventoryInstanceの除外フラグ | 新規棚卸対象、進行中の棚卸検索 | 既に記録した棚卸結果や履歴 |
| 棚卸の予定数・実数・差異 | StocktakeTarget / StocktakeRecord | 該当棚卸の記録と履歴 | 確定済みの過去結果 |
| 削除済み | Item.isArchived / 在庫status | 通常検索や棚卸から除外、管理者専用で表示 | 実際の取引・棚卸履歴 |

### 更新の仕組み
- 商品の単品編集も一括編集も同じ `syncItemLinks` を利用し、既定値からの継承中、または変更前の商品共通値と一致する在庫情報を同一トランザクション内で同期する。
- 明示的に異なる在庫値、削除済みの在庫、数量、ロット、期限、保管場所、棚卸実績は自動書き換えしない。
- nullの在庫分類は商品マスタの最新値を継承する。棚卸カテゴリの検索条件も `inventoryCategoryWhere` を共通利用する。
- 新規棚卸では `inspectionInventoryWhere` を適用し、商品全体・個別ロットの対象外設定を共通に扱う。別ロットの更新を他ロットに伝播しない。
- 商品一覧と商品詳細は `useLiveRefresh` と `fetchFresh` により最新DBを再取得する。通信失敗時は最新と断言せず、警告を表示する。

### レスポンシブ表示
- 320～767px：1列、情報を折り返せるカード、選択用44pxのタップ領域。
- 768～1279px：2列のカード、ロット詳細は必要時にだけ表示。
- 1280px以上：3列でPCの無駄な一行占有を解消。
- 一覧の一次情報：商品名、コード、メーカー、分類、単位別数量、明細数、最短期限、保管場所。
- 詳細情報：個別ロットの数量・期限・場所・履歴と編集画面は商品詳細から開く。
- 削除済みデータは管理者専用の別一覧で扱い、数量の「現在庫」誤認を防ぐ。
