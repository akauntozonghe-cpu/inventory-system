# 分類・商品・在庫・識別コードの整合性

## 正式な情報源

- 大分類・小分類の名称とラベルコード: `Classification`
- 商品のJAN、システムバーコード、管理コード、所属分類: `Item`
- 数量、Lot、期限、保管場所: `InventoryInstance`
- 保管場所名と説明: `StorageLocation`
- 発行済み分類ラベルの旧コード: `ClassificationLabelAlias`

## リアルタイム同期

- 商品の大分類・小分類・管理コード・管理区分・メーカーを変更すると、DBトリガーが同じ商品の全在庫明細へ即時反映する。
- 分類管理から商品を追加、除外、移動、分割、統合した場合も、商品と在庫明細を同一トランザクションで更新する。
- 大分類QRは分類マスターの不変な `labelCode` を格納する。名称変更後も読取時に現在の分類名へ解決する。
- 大分類を統合した場合、統合元ラベルコードは別名として統合先へ引き継ぐため、既存ラベルを読み取れる。
- 旧形式の分類名入りQRも互換入力として継続利用できる。

## 識別コードの役割

- JAN: 市販商品の検索・重複候補判定に使用する。JANだけで同一商品と断定しない。
- システムバーコード: JANがない商品を含む内部商品識別子。商品単位で一意。
- 管理コード: 利用者が定める商品管理番号。商品単位で一意。
- 分類ラベルコード: 大分類ラベル専用。商品コードやJANとして扱わない。

## 変更時に守ること

- 在庫明細の分類文字列を単独で編集せず、必ず商品または分類管理を起点に変更する。
- 分類の削除は所属商品が0件の場合だけ許可する。使用中の場合は移動・分割・統合を使う。
- 保管場所の統合時は数量、棚卸対象、棚卸記録、履歴、フリマ出品の参照を引き継ぐ。
